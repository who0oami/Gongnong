# Gloss 의미 보존 및 캡션 복구

## 현재 처리 흐름

입력 자막 → 지원하는 문법의 원문 보존 또는 로컬 LLM → 출력 검증 → CSV/영상 확인 → 수어 클립과 미매칭 캡션 혼합 표시 또는 의미 보호를 위한 입력 자막 전체 표시.

- `gloss_clause_rules.py`: -지 말고 + 요청, -지 마세요/말아 주세요/말아요/마라, 현재형 필요가/필요는 없다를 제한적으로 처리한다. 명사·숫자를 보존하고 금지는 동작과 묶는다. 인용·질문·과거형 등 지원 범위 밖은 기존 모델 경로를 사용한다.
- `gloss_output_validation.py`: 알려진 방향·아라비아 숫자·부정 표현 변경을 검사한다. 복합문 전체를 일괄 거부하지 않는다. 원문 활용 근거가 있을 때만 와다/해다/돼다를 오다/하다/되다로 보정한다.
- `local_llm_gloss_service.py`: 외국어가 포함된 출력 및 검증 실패를 한 번 재생성한다. 두 번째도 실패하면 LocalGlossValidationError를 반환한다. 연결 장애는 재생성하지 않는다. 두 요청은 120초 시간 예산을 공유하며 두 번째 요청의 타임아웃은 남은 시간으로 제한한다.
- `llm_gloss_service.py`: 출력 검증 실패를 GlossValidationError로 구분해 Job에 전달한다. 일반 provider 오류와 구분한다.
- `gloss_display_service.py`: 일반 미매칭 단어와 누락 영상은 해당 항목만 캡션으로 바꾼다. 매칭된 아바타는 유지하고 미매칭 텍스트를 구간 위에 겹쳐 표시한다. 단, 누락 항목이 부정·금지·불필요 등 의미 표지로 인식되면 긍정 동작만 재생하지 않도록 전체 입력 자막으로 보호한다.
- `routers/job.py`: 재생성 후 검증 실패도 해당 구간의 입력 자막으로 복구한다. Ollama 연결·HTTP 오류는 기존처럼 Job 실패로 처리한다. 입력 자막은 corrected_text가 있으면 이를, 없으면 source_text를 사용한다.
- `video_merger.py`: 캡션을 기본 포즈 이미지 위에 실제로 그린다. 이미지가 없으면 검은 배경을 사용한다. 영상 파일이 나중에 없어지는 경우도 캡션으로 복구한다.

출력 배열은 기존 list[str]를 유지한다. '열다 금지', '갈 필요 없다'처럼 하나의 의미 단위를 담은 표현도 허용한다. 모든 항목이 단일 사전형 단어인 것은 아니다. 신규 자산 생성이나 KNN 보정 코드는 변경하지 않았다.

## 예시

| 입력 | 보호되는 중간 표현 |
|---|---|
| 문을 열지 말고 창문을 닫으세요. | 문을 / 열다 금지 / 창문을 / 닫으세요 |
| 학교에 갈 필요가 없어요. | 학교에 / 갈 필요 없다 |
| 상자를 지키고 있지만 겁먹을 필요는 없어요. | 상자를 / 지키고 / 있지만 / 겁먹을 필요 없다 |

'필요 없다 → 의미없다'는 원문이 '필요 없다'인데 이전 모델이 '의미없다'로 오역했다는 뜻이다. 두 표현을 서로 치환하지 않는다.
위 세 예시는 현재 CSV에서 필요한 자산이 부족하므로 최종 영상에 입력 문장 전체가 표시된다. 이것을 수어 번역 성공으로 집계하면 안 된다.

## 실행 환경

기존 FFmpeg/ffprobe가 PATH에 있어야 하며 FFmpeg의 drawtext 필터를 사용한다. 새 Python 의존성은 추가하지 않았다.
한글 폰트는 KSL_CAPTION_FONT로 지정할 수 있다. 미설정 시 Windows 맑은 고딕, Linux Noto CJK/Nanum, macOS Apple SD Gothic Neo의 일반 경로를 확인한다. 파일이 없으면 폰트 설정 오류를 반환하며 글자가 깨진 성공 영상을 만들지 않는다.
폰트 파일은 임시 폴더로 복사하고 자막은 UTF-8 텍스트 파일로 전달한다. drawtext expansion을 끄므로 %{} 등을 식으로 실행하지 않는다.

```powershell
$env:PYTHONPATH = "backend"
python -m unittest tests.test_gloss_matcher tests.test_local_llm_gloss_service tests.test_gloss_output_validation tests.test_gloss_clause_rules tests.test_gloss_display_service tests.test_video_captions tests.test_gloss_error_contract -v
```

## 검증 결과

- 단위/회귀 테스트 54개: 문법 범위, 실제 CSV, 부정 보존, 재생성, 오류 구분, 영상 누락 복구, 캡션 시간·텍스트 전달 검증.
- 실제 렌더링: 세 예시를 각 2.5초로 구성한 1920×1080 MP4 생성. ffprobe로 총 7.5초 확인.
- 1초, 3.5초, 6초 프레임을 추출해 세 한글 문장의 표시를 시각적으로 확인했다.
- 이번 Local LLM 변경사항의 실제 FastAPI/DB/YouTube 전체 E2E는 이 환경에 DB 접속 설정과 API 실행 의존성이 없어 미실행. 서비스 단위 렌더링 검증과 구분한다.

## 실험 기록과 한계

[기존 프롬프트 비교](evaluations/gloss_semantics_comparison.json), [부정 범위 비교](evaluations/gloss_negation_scope.json), [구조화 비교](evaluations/gloss_structured_scope.json)는 이전 동작의 실험 기록이다. 해당 파일의 실패가 현재 원문 보호 경로에서도 그대로 발생한다는 뜻은 아니다.
[재생성 실험](evaluations/gloss_regeneration.json) 이후 원문 보호 경로와 최종 캡션 복구를 추가했다.

검증기는 한국어 의미 분석기나 번역 정확성 증명이 아니다. 지원 범위 밖 오역, 동음이의어, 자산 의미 불일치까지 모두 해결하지는 않는다. 어휘·영상이 부족하면 캡션 비율이 높아지는 보수적인 정책이다. 실제 KSL 표현과 신규 영상 자산은 별도 검토·생성이 필요하다.

## 혼합 표시 및 타이밍 정책

캡션은 해당 구간의 클립·idle 위에 오버레이하므로 추가 재생 시간을 소비하지 않는다. 단어별로 별도 시점을 추정하지 않으며 구간 동안 미매칭 표현을 함께 표시한다.
타임라인은 actual_start=max(원래 시작, 이전 실제 종료)로 계산하고 오버플로를 다음 구간에 전달한다. 여유 구간은 지연을 흡수하며 캡션만 있는 구간은 원래 읽기 시간을 유지한다. 순서를 바꾸거나 클립을 자르지 않는다. 이 정책은 긴 수어로 인한 원본 영상 대비 지연을 없애는 기능은 아니다.
클립 길이는 타임라인 항목에 기록하므로 렌더링 직전에 파일이 사라져도 예정 길이만큼 기본 포즈와 해당 항목 캡션으로 대체한다.

추가 렌더링 검증: 실제 수어 대신 1초 파란 테스트 클립과 2초 idle을 사용해, 미매칭 명사 캡션이 있어도 기존 클립이 남고 총 길이가 3초인 것을 ffprobe 및 두 프레임으로 확인했다. 이는 실제 수어 의미 검증과 구분한다. 렌더링 직전 부정 영상이 누락되는 경우는 원문 캡션으로 보호하는 회귀 테스트를 추가했다.


## 팀 통합 테스트 인계 (2026-09-22)

- 작업 출발 브랜치: `jihyun/local-llm-gloss`.
- 이전 브랜치: `jihyun/gloss-matching-validation`. 커밋 `5bf8784`에서 조사 정규화, SEN 전체 문장 매칭, 자산 감사 스크립트와 테스트를 반영했다.
- 이번 추가 브랜치: `jihyun/local-llm-semantic-integration`. 이전 브랜치에서 분기해 의미 검증, 제한적인 원문 문법 보존, 재생성, 혼합 캡션 및 타임라인 처리를 추가했다.
- 팀원 보고에 따르면 기존 Gemini Convert의 로그인, Job 생성, polling, 실패 메시지, 완료 영상 재생 E2E는 확인했다. 이번 Local LLM 교체 후 E2E 결과와는 구분한다.
- 각자 로컬 PostgreSQL을 사용하므로 공용 DB 검증 완료로 표기하지 않는다.
- 프론트 변경은 포함하지 않는다. 팀 합의인 `job_id`, `result.video_url`, `COMPLETED` 기준 통합을 전제로 하며 adapter 정리는 팀원 작업이다.

### 다음 날 실제 환경에서 확인할 순서

1. 팀원 Convert 통합 브랜치와 변경사항을 비교해 반영한다. 라우터는 양쪽에서 수정했으므로 병합 시 Job 처리 흐름을 확인한다.
2. DATABASE_URL, Local LLM provider 설정, Ollama와 모델, FFmpeg/ffprobe, 한글 폰트, CSV 코드에 대응하는 실제 영상 경로를 확인한다.
3. 로그인 후 `/translate/jobs` 생성, Job/자막 DB 저장, 상태 polling, 완료 후 `result.video_url`의 MP4 접근과 재생을 확인한다.
4. 일반 미매칭 명사 하나가 있어도 나머지 수어 클립이 유지되는지 확인한다. 부정·금지 자산 누락과 출력 검증 실패의 전체 자막 보호는 별도로 확인한다.
5. 좌우·상하, 숫자, ‘문을 열지 말고 창문을 닫으세요’, ‘학교에 갈 필요가 없어요’의 원문·생성 표현·영상 의미를 대조한다. 캡션 복구를 수어 번역 성공으로 집계하지 않는다.
6. Ollama 연결 실패, 영상 누락, 긴 클립에 따른 지연, 새로고침 resume/retry를 확인하고 캡션 대체 사례를 기록한다.

현재 업로드 목적은 통합 테스트이다. 실제 신규 수어 영상의 의미 적합성과 Local LLM 전체 E2E는 위 절차로 확인할 예정이며, 번역 품질 검증 완료를 의미하지 않는다.
