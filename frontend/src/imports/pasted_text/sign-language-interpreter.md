# 1. 개요

---

### 1.1 제품 목표

농인이 유튜브 등 영상 콘텐츠를 통역사나 자막 없이도 수어로 바로 이해할 수 있도록 지원한다. 사용자가 유튜브 영상 링크를 입력하면, 원본 영상과 AI가 생성한 수어 통역 아바타 영상을 화면에 나란히 배치(원본 3:2 / 수어 3:1)해 동기화 재생한다.

MVP에서는 유튜브 영상 하나를 입력받아 수어로 변환·재생하는 핵심 흐름에 집중하며, 향후 브라우저 확장 프로그램/오버레이 형태, 실시간 카메라 기반 수어 인식, 화상회의 통역, 수어 기반 문서 자동 작성으로 확장한다.

### 1.2 배경

농인은 영상 콘텐츠를 볼 때 자막에 의존하는 경우가 많지만, 자막은 결국 한국어 문자이고 한국수어는 한국어와 문법이 다른 독립된 언어이기 때문에 자막만으로는 완전한 이해가 어렵다. 실제로 한국수어 사용자의 90.8%가 가장 적절한 언어로 한국수어를 꼽은 반면 한글은 3.5%에 그쳤다(국립국어원, 2024).

이러한 문제를 해결하기 위해, 유니브AI와 같이 원본 콘텐츠와 보조 패널을 나란히 두는 학습 플랫폼형 UI를 참고하여, 원본 영상 옆에 수어 통역 영상을 배치하는 화면 구조를 채택한다.

실제 Text-to-Sign·Sign Avatar 모델이 완전히 연결되지 않은 MVP 환경에서는 샘플 영상과 샘플 수어 결과로 전체 흐름을 체험할 수 있는 데모를 제공하며, 모든 데모 화면에 데모 상태를 명확히 표시한다.

# 2. 문제 정의 및 솔루션

---

### 2.1 사용자 문제

농인은 유튜브 등 영상 콘텐츠를 시청할 때 자막에 의존해야 하는데, 자막은 한국어 문장 형태라 한국수어를 제1언어로 사용하는 농인에게는 이해 부담이 크다.

특히 전문 용어가 많거나 발화 속도가 빠른 영상은 자막만으로 맥락을 따라가기 어렵다. 또한 자막은 화자의 감정이나 뉘앙스를 전달하지 못해 콘텐츠 이해도가 청인 대비 떨어지는 경우가 많다.

### 2.2 해결 방안

사용자가 유튜브 영상 링크를 입력하면, 음성 인식(STT)으로 영상 속 음성을 텍스트로 추출하고, LLM으로 문맥을 이해해 문장을 정리한 뒤, Text-to-Sign으로 수어 동작 시퀀스를 생성하고, Sign Avatar가 이를 영상으로 렌더링한다.

완성된 수어 영상은 원본 영상(3:2) 옆에 수어 영상(3:1) 패널로 배치되어 동기화 재생된다. 변환 신뢰도가 낮은 구간에는 불확실성 표시를 제공하고, 사용자가 자막 보기 등 대체 옵션으로 전환할 수 있게 한다.

### 2.3 차별화 포인트

단순히 인간 통역 영상을 얹거나 수어 사전을 제공하는 것이 아니라, AI가 영상 콘텐츠 전체를 이해해 자동으로 수어 영상을 생성한다는 점이 핵심이다.

유니브AI와 유사한 '원본 콘텐츠 + 보조 패널' 레이아웃을 적용해, 농인 사용자가 기존에 익숙한 콘텐츠 소비 방식과 유사한 경험으로 수어 통역을 이용할 수 있다. 또한 변환 결과의 신뢰도를 숨기지 않고 표시하며, 실제 모델 연결 전에도 데모로 전체 사용자 경험을 검증할 수 있다.

# 3. 타겟 사용자 및 시나리오

---

### 3.1 타겟 사용자

주요 사용자는 유튜브 등 영상 콘텐츠를 즐겨 보는 농인·수어 사용자다.

보조 대상은 접근성 콘텐츠 제공 의무가 있는 기업·공공기관,
그리고 교육·콘텐츠 제공자(강의 영상, 뉴스 등에 수어 통역을 추가하고자 하는 주체)다.

사용자는 PC 또는 모바일 브라우저로 서비스에 접속하며, 자막보다 수어로 콘텐츠를 이해하는 것을 선호한다.

### 3.2 사용자 시나리오

1. 사용자가 플랫폼에 접속해 시청하고 싶은 유튜브 영상 링크를 입력창에 붙여넣는다.
2. 시스템은 영상 음성을 STT로 텍스트화하고 처리 상태(진행률, 데모 모드 여부)를 화면에 표시한다.
3. 처리가 완료되면 화면이 왼쪽 원본 영상(3:2)과 오른쪽 수어 아바타 영상(3:1)으로 분할되어 표시된다.
4. 사용자가 재생 버튼을 누르면 두 영상이 동기화되어 함께 재생된다.
5. 수어 변환 신뢰도가 낮은 구간에는 안내 표시가 뜨고, 사용자는 자막 보기 등 대체 옵션을 선택할 수 있다.
6. 시청이 끝나면 사용자는 처리한 영상을 기록에 저장하거나, 기록 목록에서 다시 불러와 재생할 수 있다. 모든 AI 미연결 기능은 '데모' 라벨과 샘플 입력 안내를 표시한다.

# 4. 핵심 지표(KPI)

유튜브 링크 입력부터 수어 영상 생성 완료까지의 성공률, 평균 처리 시간, 원본 영상과 수어 영상 간 동기화 오차, 첫 영상 완주 시청률, 신뢰도 낮은 구간 표시 후 대체 옵션(자막 전환) 클릭률, 시청 기록 저장률, 재방문율을 핵심 KPI로 관리한다.

### 4.1 목표 예시

- 영상 처리(변환) 성공률 80% 이상
- 평균 처리 시간 영상 길이 대비 일정 배수 이내 (예: 10분 영상 기준 3분 이내)
- 첫 영상 완주 시청률 60% 이상
- 동기화 오차 500ms 이내

실제 모델 도입 이후에는 표현별 수어 변환 정확도, 영상 길이·발화 속도별 처리 성능을 별도로 측정한다.

# 5. 리스크

<aside>
⚠️

1. 영상 전체를 처리한 뒤 재생하는 구조상 실시간 스트리밍 대비 처리 지연이 발생하며, 영상이 길거나 서버 부하가 클 경우 사용자 이탈로 이어질 수 있다.
2. 수어 생성 정확도가 낮을 경우 오역이 발생할 수 있으며, 특히 전문 용어·신조어·빠른 발화 구간에서 위험이 크다.
3. 유튜브 영상을 재가공해 활용하는 과정에서 저작권 이슈가 발생할 수 있어, 원본 영상을 복제·재배포하지 않고 별도 패널로 병렬 재생하는 방식의 법적 검토가 필요하다.
4. Sign Avatar의 동작이 부자연스러울 경우 사용자의 신뢰도와 이해도를 떨어뜨릴 수 있다.
5. 사용자가 데모 결과를 실제 AI 변환 결과로 오인할 위험이 있다.

---

MVP에서는 지원 범위를 명확히 고지하고, 데모 라벨 / 처리 상태 표시 / 신뢰도 표시 / 자막 대체 옵션 / 오류 신고 기능을 제공해야 한다.

</aside>

# 6. 주요 요구사항

---

### 6.1 유튜브 링크 입력 및 영상 처리 파이프라인 `중요도: 높음`

사용자가 유튜브 영상 링크를 입력하면 STT → LLM 문맥 정리 → Text-to-Sign → Sign Avatar 렌더링으로 이어지는 처리 파이프라인을 실행하고, 처리 상태를 화면에 표시한다.

<aside>

**수용 기준**

- [ ]  시작 화면에서 사용자가 유튜브 링크를 입력할 수 있다.
- [ ]  링크 입력 후 처리 진행 상태(대기·처리 중·완료)가 화면에 표시된다.
- [ ]  실제 AI·API가 연결되지 않은 경우 '데모' 상태가 표시되고 샘플 영상으로 결과를 체험할 수 있다.
- [ ]  잘못된 링크나 지원하지 않는 영상 형식은 오류 안내를 표시한다.
- [ ]  처리 완료 후 결과 화면(재생 화면)으로 자동 이동한다.
</aside>

### 6.2 원본 영상·수어 영상 동기화 재생 UI `중요도: 높음`

원본 영상(3:2)과 수어 아바타 영상(3:1)을 화면에 나란히 배치하고, 두 영상이 같은 재생 지점을 기준으로 동기화되어 재생되도록 한다.

<aside>

**수용 기준**

- [ ]  결과 화면에 원본 영상과 수어 영상이 지정된 비율(3:2 / 3:1)로 나란히 표시된다.
- [ ]  재생·일시정지·탐색(seek) 조작이 두 영상에 동시에 적용된다.
- [ ]  두 영상 간 동기화 오차가 허용 범위를 벗어나면 자동으로 재보정된다.
- [ ]  모바일 화면에서는 두 영상이 상하 또는 반응형으로 재배치되어도 비율이 유지된다.
</aside>

### 6.3 음성 인식 기반 텍스트 추출 `중요도: 높음`

영상 속 음성을 STT로 인식해 텍스트로 변환하고, 이후 문맥 정리 및 수어 변환 단계의 입력으로 사용한다.

<aside>

**수용 기준**

- [ ]  영상 음성이 텍스트로 변환되어 처리 로그 또는 자막 형태로 확인 가능하다.
- [ ]  인식 실패 구간은 별도로 표시되고 수동 확인이 가능하다.
- [ ]  데모 모드에서는 샘플 텍스트로 이후 단계를 시연할 수 있다.
</aside>

### 6.4 Text-to-Sign 변환 및 Sign Avatar 렌더링 `중요도: 높음`

정리된 텍스트를 수어 동작 시퀀스로 변환하고, Sign Avatar가 이를 영상으로 렌더링해 수어 영상 패널에 표시한다.

<aside>

**수용 기준**

- [ ]  텍스트 입력 시 수어 동작 시퀀스가 생성된다.
- [ ]  생성된 시퀀스가 Sign Avatar 영상으로 렌더링되어 재생된다.
- [ ]  변환 실패·미지원 표현은 대체 표시(자막 등)로 전환된다.
</aside>

### 6.5 처리 상태·신뢰도 표시 및 재처리 요청 `중요도: 중간`

변환 신뢰도가 낮은 구간에 안내를 표시하고, 사용자가 대체 옵션(자막 보기)을 선택하거나 재처리를 요청할 수 있도록 한다.

<aside>

**수용 기준**

- [ ]  신뢰도가 낮은 구간에는 '정확하지 않을 수 있어요' 안내가 표시된다.
- [ ]  사용자는 해당 구간에서 자막 보기로 전환할 수 있다.
- [ ]  사용자는 오류 신고 또는 재처리 요청을 보낼 수 있다.
</aside>

### 6.6 시청 기록 관리 `중요도: 중간`

처리한 영상을 기록으로 저장하고, 사용자가 이전 기록을 확인·재생·삭제할 수 있도록 한다.

<aside>

**수용 기준**

- [ ]  시청 기록 화면에서 처리한 영상 목록을 확인할 수 있다.
- [ ]  각 기록에는 영상 제목, 처리 일시, 상태가 표시된다.
- [ ]  사용자는 기록에서 영상을 다시 재생할 수 있다.
- [ ]  사용자는 개별 기록을 삭제할 수 있다.
</aside>

### 6.7 접근성 중심 반응형 인터페이스 `중요도: 높음`

농인·수어 사용자가 PC와 모바일 모두에서 빠르게 사용할 수 있도록 명확한 레이아웃과 높은 명암 대비를 적용한다. 주요 화면은 시작(링크 입력) 화면, 재생(동기화 영상) 화면, 시청 기록 화면, 확장 서비스 안내 화면으로 구성한다.

<aside>

**수용 기준**

- [ ]  모바일·PC 화면 모두에서 원본·수어 영상 패널 비율이 유지되거나 반응형으로 재배치된다.
- [ ]  높은 명암 대비의 색상 체계가 적용된다.
- [ ]  시작 화면에 링크 입력과 처리 상태가 명확히 표시된다.
- [ ]  재생 화면에서 두 영상, 신뢰도 표시, 자막 전환 옵션에 쉽게 접근할 수 있다.
- [ ]  시청 기록 화면, 확장 서비스 안내 화면으로 이동할 수 있다.
- [ ]  데모 기능은 모든 관련 화면에서 '데모' 라벨과 제한사항을 표시한다.
</aside>
